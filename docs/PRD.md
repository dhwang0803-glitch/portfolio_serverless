# Portfolio (Serverless) — PRD

- **작성일**: 2026-06-15
- **상태**: Draft

## 목표

개인 포트폴리오를 보여주는 **백엔드 없는 순수 정적 서버리스 웹사이트**. Vercel 배포.

## 사용자 시나리오

1. 방문자가 메인 페이지에서 **간단한 소개 + 기술 스택**을 본다.
2. 메인 페이지의 **프로젝트 갤러리**에서 포트폴리오마다 1장짜리 요약 카드를 본다.
3. 요약 카드를 클릭하면 **해당 포트폴리오 상세 페이지**로 이동한다.
4. 상세 페이지에서 본문 + 첨부 파일(PDF/PPTX) + GitHub 링크를 본다.
5. 어디서든 **연락처(이메일)**, **이력서 다운로드**에 접근한다.

## 핵심 기능 (MVP)

- 소개(About): 자기소개 + 기술 스택
- 프로젝트 갤러리: 포트폴리오 요약 카드 목록 (메인 페이지)
- 프로젝트 상세: 카드 클릭 시 상세 내용 + 첨부 파일 + GitHub 링크
- 연락처: 이메일 (mailto)
- 이력서 다운로드: 정적 파일 다운로드

## 비기능 요구

- **백엔드 없음**: 서버리스 함수/DB 불필요. 빌드 타임 정적 생성(SSG)만.
- **호스팅**: Vercel
- **성능**: 정적 자산 + 이미지 최적화. 첫 로드 가벼움.
- **콘텐츠**: 파일 기반 — 포트폴리오마다 콘텐츠(요약/상세) + 첨부(PDF/PPTX)를 추가하면 빌드에 포함.

## 스택 결정

- **프론트엔드: Next.js (App Router, 정적 생성/`output: export`)** 를 1순위로 채택.
  - 이유: 파일 기반 라우팅으로 `/projects/[slug]` 상세 페이지가 자연스럽고, SSG·이미지
    최적화·Vercel 배포가 1급 지원. 콘텐츠(MDX/데이터) → 정적 페이지 생성에 적합.
  - 대안 검토: **React + Vite** — 가볍지만 파일 기반 라우팅/SSG가 기본 제공이 아니라
    react-router + 수동 프리렌더가 필요. 포트폴리오의 "프로젝트마다 1페이지" 요구에
    Next.js가 더 맞아 1순위에서 제외(ADR 후보).

## 콘텐츠 관리 방식

- 포트폴리오 1건 = 콘텐츠 디렉토리 1개: `content/projects/<slug>/`
  - `index.mdx` (또는 `meta.ts`) — frontmatter: `title`, `summary`, `thumbnail`, `github`, `date`, `files[]` + 본문(상세)
  - `assets/` — 첨부 PDF/PPTX 원본
- 프로필/연락처/이력서 경로는 `content/profile.ts` 단일 파일로 관리.
- **PDF/PPTX 처리**: PDF는 상세 페이지에 인라인 미리보기(iframe) + 다운로드 링크.
  PPTX는 브라우저 인라인 미리보기가 어려워 **다운로드 제공**(원하면 빌드 전 PDF 변환본 추가로 미리보기). 이력서도 PDF 권장.

## 범위 밖 (이번 MVP 제외)

- 블로그/CMS, 방문 분석, 연락 폼 전송(서버리스 함수), 다국어, 다크모드 토글(후속).
